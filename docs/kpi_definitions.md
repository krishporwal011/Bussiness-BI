# KPI dictionary

All metrics use the cleaned, eligible basket population generated by `src/clean_data.py` unless a report explicitly says otherwise.

| KPI | Definition | Grain / notes |
|---|---|---|
| Basket | One valid `InvoiceNo` transaction identifier | Distinct normalized `basket_id` |
| Basket count | Count of distinct valid baskets | Includes single-item baskets |
| Item | One normalized merchandise `StockCode` | Product description is a label |
| Basket-item presence | One distinct `(basket_id, item_key)` row | Quantity does not create extra presence |
| Pair count | Distinct baskets containing both items | Unordered pair; duplicate lines cannot inflate it |
| Support(A,B) | `pair_count(A,B) / eligible_basket_count` | Single-item baskets remain in denominator |
| Confidence(A → B) | `pair_count(A,B) / basket_count(A)` | Directional |
| Confidence(B → A) | `pair_count(A,B) / basket_count(B)` | Directional |
| Lift(A,B) | `support(A,B) / (support(A) × support(B))` | Symmetric; 1 indicates independence under the standard interpretation |
| Average basket size | `distinct basket-item presence rows / basket count` | Presence-based, not unit quantity |
| Single-item basket % | `single-item basket count / basket count` | Single-item baskets are retained |

## Pair-key rule

Every pair is stored once with `item_a_key < item_b_key` using the normalized, uppercase item key. The rule is applied in Python and SQL and is required in Power BI to avoid counting `(A,B)` and `(B,A)` as separate pairs. Both directional confidence measures are still reported.

## Ranking rule

The default thresholds are configurable in `config/analysis_config.json`:

1. Keep items with basket frequency at least 5.
2. Keep pairs with pair count at least 20 and support at least 0.001.
3. Require both directional confidence values to meet `min_confidence` (0.0 by default).
4. Rank by pair count descending.
5. Break ties by lift descending, then normalized item names ascending.

The supplementary lift-ranked table uses lift descending, pair count descending, then normalized item names ascending. Lift-ranked results must be read with pair count and support because high lift can arise from relatively rare co-occurrences.

## Cleaning assumptions

The default population excludes cancellations/returns, non-positive quantities, invalid prices, missing basket/item/name/date fields, known service or adjustment codes, test rows, and exact duplicate source rows. Missing customer IDs are retained when the basket and item are valid. These are analysis assumptions, not changes to the raw source.
